# EOS NEXUS — Ultimate Engineering Intelligence

## Objective
Implement a premium, event-driven desktop Mission Control for EOS, faithfully following the animated design in [eos-nexus-mission-control.svg](assets/eos-nexus-mission-control.svg). Keep the dark obsidian surfaces, cyan/violet rotating CEO rings, moving directional packets, specialist nodes, skill intelligence, runtime metadata, security radar, event stream and inspector. The SVG is a simulated design reference, not evidence of implementation.

## Audit first
Inspect the actual local checkout, current active EOS version, public and internal repositories, release manifests, host adapters, registries, hook contracts, evidence and test suites. Preserve existing user changes. Do not assume the older README is current. Enumerate every discovered mechanism and classify its capability and runtime evidence separately. Do not invent agents, tools, skills, integrations or security guarantees. Keep internal or sensitive material out of the public repository.

## Runtime coverage
Discover all components dynamically, without hardcoded inventories: chief-architect (display label CEO), specialists, nested delegation and orchestration, project resolution/context, skill discovery/selection/loading/use, host/model/provider, MCP/tool/terminal calls, Graphify freshness and coverage, external providers such as Ruflo, Guardian/EDR/permissions when present, secret scan, policy decisions, quality gate, evidence, promotion, version management and rollback. Distinguish discovered, selected, loaded, invoked, completed, denied, failed, unavailable and unknown. A skill being selected does not prove it was loaded or used. A registered agent does not prove execution. An adapter probe does not prove delegation. Never claim access to hidden model reasoning; show only observable events and recorded decision summaries. Show actual model name, token usage, latency and cost only when supplied by the host; otherwise unknown.

## Desktop experience
- Main screen: central CEO core with multiple counter-rotating rings, pulse on actual coordination, readable surrounding graph, animated directed data transfers only during observed activity; retain the reference design.
- Additional views: n8n-style workflow, expandable nested agent tree, Security Operations radar, project/Graphify map, timeline and replay.
- Click nodes/edges to inspect real event details, originating agent, selected skill and selection reason, tool inputs/results with secrets redacted, policy decision, duration and evidence reference. Include zoom, pan, drag, fit, fullscreen, filters and search.
- Skill panel: distinguish installed/discovered, selected, loaded, in use, rejected, unavailable and unknown; show provenance, reason, agent, version and evidence when available.
- Multi-host/multi-project sessions, separate graphs and event streams, global overview; no session mixing.
- Auto-open on a supported EOS activation, at most once per session unless explicitly reopened. Single-instance desktop window, persistent settings: auto-open, open minimized, system tray, close behavior, pause, quiet mode, animations, notifications, reduced motion and optional OS startup.
- Closing the window never stops EOS or its host. If auto-open is disabled, never force it open. Tray and close semantics must be explicit; reopen manually. Pause/close/minimize suspends animation and unnecessary rendering; observation and evidence behavior follows configured policy.
- Turkish and English localization; accessible keyboard controls, contrast and reduced-motion fallback.

## Engineering
Use a read-only, local-first observer separate from EOS decision authority. Prefer the existing telemetry and event contracts; add minimal compatible instrumentation at actual event sources only. Evaluate Tauri/Rust and TypeScript/React Flow or GPU-accelerated Canvas/WebGL against actual architecture and benchmarks; justify selection. Use authenticated local IPC, ordered versioned events, session/task/agent/correlation IDs, timestamp, source, status, duration, severity and evidence references. Implement deduplication, reconnect, bounded queues, event loss reporting and session isolation. No additional model calls or token usage from the observer. No external analytics or cloud upload by default. Redact secrets and validate untrusted event data. Never allow the UI to weaken permissions or gates. Distinguish host permissions from OS sandbox enforcement. Live, stale, disconnected, replay and simulation must be visibly distinct; do not fake events, counters, successful checks or activity. Idle nodes remain still; cosmetic ambient animation must not imply work. Archive local sanitized sessions with configurable retention, playback speed, seeking and export.

## Acceptance
Record baseline before modifications. Implement in small reversible steps: audit, event layer, desktop shell, animated graph, skill/tool/security inspectors, replay, performance, installer integration. Test real host sessions on Windows and any other platform only where available. Prove actual activation, automatic open and persistent opt-out, closing without interrupting EOS, single-instance operation, correct skill state transitions, real nested delegation/parallelism, security denial, quality gate evidence match, session isolation, disconnect/reconnect, secret redaction, replay accuracy, no additional LLM calls, bounded CPU/GPU/RAM and no existing install/update/rollback or permission regressions. Aim for smooth 60 FPS on supported hardware and measure rather than claim it. Report exact tests and artifacts; mark untested hosts/platforms as unverified. Do not publish a production release without approval.

Deliver working code, tests, integration instructions, and a truthful completion report. Do not stop at a mockup. Every active light must correspond to a real event; every active agent to observable execution; every security/gate result to verified evidence.
