# EOS 0.6.1 — Benchmark Validity, Real Pilots and P6 Trust

Date: 2026-11-21
Base: `eos/p6-metrics-0.6.0` @ `95fefd0fe810`
Decision: `edr-20261121T102525-a20300` (STANDARD)

This release exists because 0.6.0 could report a P5 score without proving that
the artifacts behind it were trustworthy. It also strengthens four weak P5
scenarios that measured metadata rather than behaviour.

## 1. P6 is now honest about its own data

| Before | After |
| --- | --- |
| no artifacts → exit 0 | no artifacts → `NO_DATA`, exit 4 |
| corrupt JSON silently skipped | `corrupt` is counted and turns the verdict `PARTIAL` |
| no integrity check | gate artifacts are trusted only when the log hash matches; P5 artifacts only when the seal matches |
| P5 and vnext_dev runs could be counted twice | identical result identities are de-duplicated (`duplicates_ignored`) |
| no version metadata | every P5 artifact carries `scenario_version`, source commit, host and two hashes |
| old and new scenarios compared | different `scenario_version` values are never trended against each other |
| every report was effectively a pass | verdicts: `VERIFIED` (exit 0), `PARTIAL` (2), `UNVERIFIED` (3), `NO_DATA` (4) |
| historical failures could be hidden | all valid gate artifacts in the window are counted, including FAIL |

**P5 artifact integrity:** `content_sha256` identifies the result (scenario
version + commit + scenarios + scorecard, without durations); `artifact_sha256`
seals the whole file. P6 verifies the seal and de-duplicates by identity.

**P6 selftest:** 12/12 cases, including: tampered gate, corrupt artifact,
wrong schema, legacy P5, duplicate run, cross-version, a repeated failure
becoming a proposal, and no proposal being auto-applied.

## 2. P5 scenarios that were strengthened

| Scenario | 0.6.0 measured | 0.6.1 measures |
| --- | --- | --- |
| cross-process | an import edge | a second **real process** is refused because another process owns the work task |
| math | that a test file exists | a four-check oracle (unit, scaling, zero boundary, square units) rejects a wrong formula and accepts the fix; impact still lists the test |
| new project | a pre-registered profile | an **unregistered** project is mapped by explicit path and is never silently gated; the refusal reason is asserted |
| security | only `secret_scan` | a real authorization oracle: a missing role check fails, a correct role check passes |
| healthy control | metadata allow | a real `write_gate` allow with an approved decision, unchanged python project |

`SCENARIO_VERSION = 2026-11-21.2`. Latest run: **18/18**, detection **1.0**,
false PASS **0**, false BLOCK **0**, context freshness **1.0**, 14.2 s,
0 model calls.

The oracle scenarios prove the fixture oracle is meaningful (broken fails,
fixed passes). They do **not** prove that an agent finds the defect; that is
P5-C and it is BLOCKED.

EOS reports them; it does not decide which copy is canonical.

## 5. P6 improvement loop (started, not autonomous)

`p6_metrics.py` now classifies repeated failures (`concurrency`,
`guard_or_routing`, `map_accuracy`, `benchmark`, `gate`) and emits proposals
with evidence, a hypothesis, an action and a verification requirement.
Every proposal is `auto_apply: false`.

It does not change routing, policy or security rules. A proposal is only
accepted after a fixture and a regression test show the measured benefit.
